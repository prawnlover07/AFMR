# AFMR 0.5.2 test report - October 21, 2026

No AFMR defect was reproduced in this session. **227 regression tests pass**, and **87 distinct native/persistence checks were validated** across the completed playback and corrected persistence runs. Additional UI checks passed. The published 0.5.2 JAR is unchanged; no replacement build is needed.

## Test setup

Minecraft 26.3, NeoForge 26.3.0.90, Java 25, Windows 11. The packaged release JAR was loaded from the isolated profile's mods folder, including its nested decoder dependencies. A separate test-only mod exercised the real runtime and sampled OpenAL channel state, position and gain on Minecraft's sound executor. These checks used actual native audio, rather than a fake audio implementation. Real keyboard and mouse inputs exercised the UI separately.

All state-changing work used a copied test world, an isolated configuration and generated audio/import fixtures. Personal music and foobar files were not modified. The test game was closed afterward.

## Validated behavior

| Area | Result |
| --- | --- |
| Real pause | Local WAV and vanilla streams enter OpenAL's paused state; playback offset remains fixed, then advances on the same source after resume. |
| Pause timing | Native fade-in/fade-out gain and position freeze; silence remains held. Queued Next and overrides start after resume. A preview paused during stream startup remains paused. |
| Minecraft interaction | Global sound resume preserves AFMR pause. Opening and closing Minecraft's actual pause menu also leaves AFMR paused. Ambient audio continues during AFMR pause. Sound reload and restart clear explicit pause. |
| Next and overrides | Next bypasses silence, preserves held and one-song overrides with Automatic off, and avoids immediate repeats. One-song completion returns to automatic selection. Empty, deleted and fully disabled override targets release or refuse correctly. |
| Shuffle | Four songs remain unique through two cycles, including the cycle boundary repeat guard. |
| Entry and exit | All four combinations pass. A retained song keeps its source through A to B to C; returning to A avoids restarting it. |
| Environments | Day/night outside, enclosed darkness, lit Underground, cover plus Y cutoff, captured Home, and whole-dimension Nether/End darkness switches pass. A custom rule combining biome, time, dimension, elevation, temperature and cover matches; failing one condition falls through. |
| Combat/death | Runtime attack trigger and forced Combat with global combat detection off pass. Cut while paused, immediate configured death fade, no new music while dead, deferred fade while paused, Finish song, and respawn pass. |
| Formats/recovery | Packaged MP3, FLAC, OGG, WAV, 24-bit FLAC/WAV and float WAV streams reach native playback. An intentionally invalid MP3 is quarantined; Retry failed clears the error and playback recovers. |
| Persistence | Saved priority, biome filter, separate entry/exit switches, timing defaults, 5,000 scanned tracks and physical Next/Pause bindings survive restart. |

The [validated case list](evidence/2026-10-21/validated-cases.txt) records all 87 distinct checks. The persistence run also passed an extra fixture-presence assertion, excluded from that total.

## UI and import checks

- Inspector Next/Pause buttons and physical Next/Pause/Inspector bindings work. The pause binding is ignored in an open Inspector, and typing Next/Pause keys in chat does not trigger music actions.
- Explorer folder/file dialogs work. A scan of **5,000 generated WAV files** displayed discovery and tag-reading progress, completed with **zero reported issues**, and left music playing. All 5,000 entries were saved and reloaded.
- A generated `.fplite` imported into an existing manual playlist. The report correctly showed **1 added, 1 already assigned, 0 new library tracks, 1 skipped missing file, 1 duplicate and 2 reused metadata entries**. Source playlist and generated WAV checksums stayed unchanged.
- Creating/naming a playlist, visiting all four condition pages, capturing the current biome, moving the playlist to priority #1, and independently enabling entry/exit finish switches work.
- Restore Minecraft defaults succeeds with invalid unsaved timing text. It restores **600/1200 seconds, fade 0, buffer 0**. Comparing the complete saved configurations confirmed every other setting, playlist and assignment remained unchanged.

Screenshots: [scan progress](evidence/2026-10-21/scan-progress.png), [paused Inspector after Minecraft menu resume](evidence/2026-10-21/paused-inspector.png).

## Performance scope

With **70,000 additional unused library entries** and a small assigned playlist, a focused 2,000-call measurement of the real playback engine measured approximately **0.3 microseconds median and p95 per call** in the final run. This checks indexed scheduling with many unrelated tracks. It does not measure full client tick time, rendering FPS, disk access, or the cost of assigning all 70,000 songs to one active playlist. The separate 5,000-file UI scan verified visible progress and successful completion, not an FPS benchmark.

## Test-fixture corrections and remaining work

Early helper errors were corrected before accepting results: singleton initialization timing, a player falling below the test Y, looping streaming offsets, asynchronous MP3 startup, and comparison against old GLFW key codes instead of this build's SDL input. The corrected checks were rerun. No AFMR production code was changed. The decoder-error case intentionally produces an audio error to verify recovery.

The [remaining deeper-test checklist](../../DEFERRED-TESTING.md) retains hardware Stream Deck checks, multiplayer/modded environments, difficult live shuffle/transition mutations, device changes and longer real-library sessions. Existing ReplayGain waveform/tag regressions pass; subjective listening across the user's library remains separate.
