# Optional loudness scanner — October 21, 2026

This covers the unreleased scanner in the current source, separately from the
earlier native 0.5.2 session. Original music and foobar data were not used or modified.
No game or desktop interaction was performed for these scanner checks.

## Automated checks

The full Java 25/NeoForge build passes **253 tests** (227 baseline plus 26 loudness
checks). Existing ReplayGain tests now distinguish missing/invalid gain from valid
0 dB tags, while retaining format parsing, waveform and peak-protection checks.

New checks cover reference calibration at common rates, mono/stereo energy,
different input levels reaching the shared target, chunk-size independence,
absolute/relative gates, silence/short clips, invalid PCM formats, peak limits,
all seven supported decoder fixture variants, valid zero-tag precedence, malformed
gain fallback, missing peak tags, unchanged-cache reuse, changed size/mtime,
waiting/resuming/cancelling jobs, concurrent-batch rejection, partial cancellation,
per-file failures, vanilla exclusion, disabled local assignments, snapshots and
JSON persistence. Playback gain resolution verifies cache validity and that tags
replace cached gain rather than multiplying it.

Scans preserve generated source bytes and modification timestamps. Test tags are
written only to temporary generated copies before scanning. No original music or
foobar data is opened by these tests.

## Independent measurement comparison

Using the installed local FFmpeg 7.1 executable, generated PCM16 fixtures were
measured independently with `-af ebur128=peak=sample -f null -`. Each contains
2 s silence, 4 s 100-Hz tone (0.2 peak), 4 s 3-kHz tone (0.05 peak), 2 s seeded
LCG noise (0.2 peak), then 2 s silence. Mono and stereo cases use the same generation
formula retained in `LoudnessMeterTest.mixedSpectrumAndGatingMatchIndependentFfmpegReferences`.

| Rate | AFMR mono LUFS | FFmpeg mono LUFS | AFMR stereo LUFS | FFmpeg stereo LUFS |
| --- | ---: | ---: | ---: | ---: |
| 8,000 | -19.6658 | -19.7 | -16.6722 | -16.7 |
| 11,025 | -19.5965 | -19.6 | -16.5730 | -16.6 |
| 22,050 | -19.4751 | -19.5 | -16.4746 | -16.5 |
| 44,100 | -19.4256 | -19.4 | -16.4191 | -16.4 |
| 48,000 | -19.4235 | -19.4 | -16.4141 | -16.4 |
| 96,000 | -19.3973 | -19.4 | -16.3761 | -16.4 |
| 192,000 | -19.3723 | -19.4 | -16.3693 | -16.4 |

The largest difference from FFmpeg's rounded one-decimal summary is **0.0342 LU**.
This does not establish meter certification or behavior on all possible signals.
The regression references allow 0.08 LU, including FFmpeg's displayed rounding.

Algorithm references: [ITU-R BS.1770-5](https://www.itu.int/dms_pubrec/itu-r/rec/bs/R-REC-BS.1770-5-202311-I!!PDF-E.pdf),
[EBU Tech 3341](https://tech.ebu.ch/docs/tech/tech3341.pdf), and the
[libebur128 rate-adjusted filter reference](https://github.com/jiixyj/libebur128).
The shared -18 LUFS playback target follows the
[ReplayGain 2.0 convention](https://github.com/Moonbase59/loudgain).
The fixed 0.01-LU histogram quantizes relative-gate membership; no whole-track PCM
storage is used. Peak protection uses decoded sample peaks, not oversampled true peaks.

## Component timing and packaging

A warmed Java 25 microbenchmark fed 120 s of generated 48-kHz stereo PCM to the
meter. After three warmups, the median of seven thread-CPU measurements was
**78.1 ms**, about **1,536 times real time**. Each lane has 160,016 bytes of histogram
arrays plus its 16-KiB PCM input buffer and small filter state. These figures exclude
decoder/metadata/disk work, job/report allocations, Minecraft and the save snapshot.
They are component measurements, not gameplay FPS or full-playlist scan timings.

The build and `sourceZip` pass. Generated verification audio/logs remain under
ignored `build/loudness-check`; generated artifacts and caches are excluded from
source packaging. No new runtime dependency or external FFmpeg requirement was added.
